** Colors with css
*** RGB (Red Green Blue)

Read this link for [[https://www.davemorrowphotography.com/color-theory-photography][color theory]]

RGB model: Every color can be represented by a combination of RED, GREEN, BLUE.

Each of the 3 base colors can take a value between 0 and 255, which leads to 16.8 million diffrent colors.

So if we want complete RED color, it will be RED in complete maximum 255 and other colors at 0. Example: R(255), G(0), B(0).

Same for other colors too. If we want complete color of one kind, give it 255 and others 0.

White: All the Red, Green, Blue at maximum of 255.
When all colors in all 3 channels are the same, we get a grey color. So all numbers must be same: rgb(0,0,0) / #000000 / #000 This will be black. rgb(69, 69, 69) / #444444 / #444 this is more grey. rgb(183, 183, 183) / #b7b7b7 This is more lighter grey.

Other complementary colors will have mix of 2 colors. Ex: Yellow: Red(255), Green(255), Blue(0).

We define colors 2 ways in css:
- RGB/RGBA Notation
- Hexadecimal Notation

What is GRB with transparency ("alpha")?
RGB with Alpha is RGB with transparency. Ex: rgba (0, 255, 255, 0.3)

Hexadecimal notation:
Instead of using a scale from 0 to 255, we go from 0 to ff (255 in hexadecimal numbers). Ex: #00ffff (this can be also shorthand to #0ff)

*** Export and Import

The purpose of *export* is to make a variable, function, class, or object
available to other JavaScript files.

Without exporting, everything defined in a file is private to that file.

Example:

File: math.js

#+begin_src javascript
export const add = (a, b) => {
    return a + b;
};
#+end_src

Another file can then import and use it.

File: app.js

#+begin_src javascript
import { add } from "./math.js";

console.log(add(2, 3));
#+end_src

Flow:

math.js
---------
export add
      |
      v
app.js
---------
import add
use add()

Mental model:

- export = "I'm making this available to other files."
- import = "I want to use something another file made available."

Notice that the names match.

#+begin_src javascript
// math.js
export const add = (a, b) => a + b;
#+end_src

#+begin_src javascript
// app.js
import { add } from "./math.js";
#+end_src

The 'add' being imported is the same function that was exported.

**** React example

Components are exported in the same way.

#+begin_src javascript
// Button.jsx
export const Button = () => {
    return <button>Click me</button>;
};
#+end_src

Another component imports and uses it.

#+begin_src javascript
// App.jsx
import { Button } from "./Button";

function App() {
    return <Button />;
}
#+end_src

Summary:

1. Define a function.
2. Export it from its file.
3. Import it where needed.
4. Use it like any other function.

This is one of the core ideas of modern JavaScript and React. It allows code to
be organized into small, reusable modules instead of putting everything into a
single large file.

**** Summary
A Promise in JavaScript is an object that represents a value that you don't have yet, but will get later.

Think of it like ordering food at a restaurant:

You order food → you get a receipt (the Promise)
The kitchen is working → the Promise is pending
Food arrives → the Promise is fulfilled (resolved)
Kitchen fails → the Promise is rejected

In JavaScript, Promises are mostly used for things that take time, like:

- fetching data from an API
- reading files
- waiting for a timer
- database queries
**** Example

#+BEGIN_SRC js
const pizzaOrder = new Promise((resolve, reject) => {
  const pizzaReady = true;

  if (pizzaReady) {
    resolve("Your pizza is ready!");
  } else {
    reject("The pizza shop is closed.");
  }
});
#+END_SRC

At this point, pizzaOrder is a Promise. It does not immediately contain "Your pizza is ready!". It represents the possibility that you'll get that value later.

Getting the result with .then():

#+BEGIN_SRC js
 pizzaOrder.then((message) => {
  console.log(message);
}); 
#+END_SRC

Result is: Your pizza is ready!

.then() runs when the Promise succeeds.

Handling errors with .catch():

#+BEGIN_SRC js
  pizzaOrder
      .then((message) => {
  	console.log(message);
      })
      .catch((error) => {
  	console.log(error);
      }); 
#+END_SRC

**** Real world Example
Imagine getting a user's profile from a server:

#+BEGIN_SRC js
function getUser() {
  return fetch("https://api.example.com/user");
}

getUser()
  .then((response) => {
    console.log(response);
  })
  .catch((error) => {
    console.log("Something went wrong:", error);
  });
#+END_SRC

fetch() does not instantly return the user data. It returns a Promise because the browser needs time to talk to the server.

**** The newer way: async / await
Most modern JavaScript uses Promises with async/await because it looks more like normal code:

#+BEGIN_SRC js
async function showUser() {
  try {
    const response = await fetch("https://api.example.com/user");
    console.log(response);
  } catch (error) {
    console.log(error);
  }
}

showUser();
#+END_SRC

then

#+BEGIN_SRC js
 const response = await fetch(...) 
#+END_SRC
means:

"Pause this function until the Promise finishes, then give me the result."

A good beginner mental model:

Promise
    |
   ├── pending   (waiting)
    |
   ├── resolved  (success → .then())
    |
    ── rejected  (failure → .catch())

     
**** Async and Await

`async` and `await` are a cleaner way to work with Promises. They let you write asynchronous code that *looks more like normal synchronous code*.

Before =async/await=, you usually wrote:

#+begin_src js
getData()
  .then(result => {
      console.log(result);
  })
  .catch(error => {
      console.log(error);
  });
#+end_src

With =async/await=, you can write:

#+begin_src js
async function run() {
    try {
        const result = await getData();
        console.log(result);
    } catch (error) {
        console.log(error);
    }
}
#+end_src

Both versions do the same thing. =async/await= is simply easier to read.

**** 1. =async= means "this function returns a Promise"

Example:

#+begin_src js
async function hello() {
    return "Hello";
}
#+end_src

Even though it looks like it returns a string:

#+begin_src js
return "Hello";
#+end_src

JavaScript actually wraps it in a Promise.

So this works:

#+begin_src js
hello().then((message) => {
    console.log(message);
});
#+end_src

Output:

#+begin_example
Hello
#+end_example

It is basically equivalent to:

#+begin_src js
function hello() {
    return Promise.resolve("Hello");
}
#+end_src

**** 2. =await= means "wait for this Promise to finish"

Example:

#+begin_src js
function getPizza() {
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve("🍕 Pizza is ready");
        }, 3000);
    });
}

async function orderPizza() {
    console.log("Ordering...");

    const pizza = await getPizza();

    console.log(pizza);
}

orderPizza();
#+end_src

Output:

#+begin_example
Ordering...
(wait 3 seconds)
🍕 Pizza is ready
#+end_example

This line:

#+begin_src js
const pizza = await getPizza();
#+end_src

means:

#+begin_quote
Start =getPizza()=. When the Promise resolves, put the result into =pizza=.
#+end_quote

It is similar to:

#+begin_src js
getPizza().then((pizza) => {
    console.log(pizza);
});
#+end_src

**** 3. Important: =await= does NOT block JavaScript

This confuses many beginners.

Example:

#+begin_src js
async function test() {
    console.log("A");

    await new Promise(resolve => {
        setTimeout(resolve, 3000);
    });

    console.log("B");
}

test();

console.log("C");
#+end_src

Output:

#+begin_example
A
C
(wait 3 seconds)
B
#+end_example

JavaScript did *not* freeze.

It paused *only the =test()= function*, while the rest of the program continued running.

Think of =await= as saying:

#+begin_quote
Pause this async function until the Promise finishes.
#+end_quote

It does *not* pause the entire program.

**** 4. Handling errors

With Promises:

#+begin_src js
getPizza()
    .then(result => console.log(result))
    .catch(error => console.log(error));
#+end_src

With =async/await=:

#+begin_src js
async function order() {
    try {
        const pizza = await getPizza();
        console.log(pizza);
    } catch (error) {
        console.log(error);
    }
}
#+end_src

=try/catch= replaces =.then()= and =.catch()=.

**** 5. Your earlier Promise example with =async/await=

Promise version:

#+begin_src js
const event = new Promise((resolve, reject) => {
    const name = "abe";

    if (name === "abe") {
        resolve(name);
    } else {
        reject("No match");
    }
});

event.then((name) => {
    console.log(name);
});
#+end_src

Async/await version:

#+begin_src js
const event = new Promise((resolve, reject) => {
    const name = "abe";

    if (name === "abe") {
        resolve(name);
    } else {
        reject("No match");
    }
});

async function checkName() {
    try {
        const name = await event;
        console.log(name);
    } catch (error) {
        console.log(error);
    }
}

checkName();
#+end_src

This line:

#+begin_src js
const name = await event;
#+end_src

means:

#+begin_quote
Wait until =event= finishes. If it resolves, store the resolved value in =name=.
#+end_quote

If the Promise had:

#+begin_src js
resolve("abe");
#+end_src

then after =await=:

#+begin_src js
name === "abe";
#+end_src

If it had:

#+begin_src js
reject("No match");
#+end_src

execution jumps directly to the =catch= block.

**** 6. Comparing =return= and =resolve=

A normal function:

#+begin_src js
function getName() {
    return "abe";
}

const name = getName();
console.log(name);
#+end_src

A Promise:

#+begin_src js
const event = new Promise((resolve) => {
    resolve("abe");
});

event.then((name) => {
    console.log(name);
});
#+end_src

An async function combines these ideas:

#+begin_src js
async function getName() {
    return "abe";
}

async function run() {
    const name = await getName();
    console.log(name);
}

run();
#+end_src

Even though =getName()= uses =return=, because it's marked =async=, JavaScript automatically wraps the returned value in a Promise.

**** Mental model

Think of it like ordering food at a restaurant.

#+begin_example
Order food
    |
    v
Kitchen starts cooking
    |
    v
You continue talking with friends
    |
    v
Food is ready
    |
    +--> Success -> resolve(food)
    |
    +--> Problem -> reject(error)
#+end_example

With =.then()=:

#+begin_src js
orderFood()
    .then(food => eat(food))
    .catch(error => complain(error));
#+end_src

With =async/await=:

#+begin_src js
async function dinner() {
    try {
        const food = await orderFood();
        eat(food);
    } catch (error) {
        complain(error);
    }
}
#+end_src

Both do the same thing. =async/await= is simply easier to read because it looks like ordinary step-by-step code.

**** Beginner Mental Model

- =Promise= a box that will contain a value later.
- =resolve(value)=  put a successful value into the box.
- =reject(error)=  put an error into the box.
- =.then()=  "When the box is ready, give me the value."
- =async= "This function always returns a Promise."
- =await= "Pause this async function until the Promise has a result."

You'll use this constantly in React:

#+begin_src js
async function fetchUsers() {
    const response = await fetch("/api/users");
    const users = await response.json();

    console.log(users);
}
#+end_src

This is the standard way modern JavaScript and React applications perform asynchronous operations.
